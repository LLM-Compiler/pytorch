FIXES (uncommitted; backup in numa_tp_correctness_fixes.patch)

  1. wrapper.py  _NumaGraphOutputCopyLine
     A replicated per-socket result that is also a graph output was never
     reconciled -- the caller got unwritten memory.

  2. numa_tp_common.py  merge_global_shard_plan
     One global shard plan per pass was OVERWRITTEN per block, so only the
     last block was described and earlier blocks' reductions were never
     emitted.

  3. wrapper.py  _numa_reduction_reclones
     Buffer-reuse aliasing clobbered the post-reduction cache entry, pointing
     consumers back at pre-reduction partials.

  4. wrapper.py  in_out_ptr args  [THIS SESSION]
     A first-seen in_out_ptr arg was given uninitialized per-socket storage
     on the theory that the kernel overwrites it. Inductor picks in_out_ptr
     for the in-place accumulate case, so the incoming value is live. The
     all-reduced MLP output feeding the fused residual add was replaced by a
     fresh zero page on every socket: the MLP contributed exactly nothing.
     Proof: NUMA output was bit-identical (max_abs=0.0) to a standard compile
     with mlp_fc2_w zeroed.
     Fix: replicate the master buffer (clone, uncached) instead.

  5. numa_tp_common.py  merged_global_shard_plan  [THIS SESSION]
     The graph-wide fallback plan read _numa_attention_tp_shard_plan and fell
     back to the MLP slot only if that was absent. With BOTH passes on -- the
     configuration the benchmarks actually run -- the MLP's template kernels
     were described by the attention plan, in which no MLP weight appears.
     Every MLP arg took the "replicate unknown tensor" path (no sharding) and
     has_row was false, so no all-reduce. The MLP collapsed to shard 0.
     Either pass ALONE was correct, which is why isolation testing missed it.
     Fix: union the generalized lists from every pass's plan.
     Also: x_nodes is now a set, so each block/pass keeps its activation
     input out of the persistent weight cache.

MECHANISM: baseline per-token cost grows 1.14 -> 3.24 ms/token across the
sweep; the NUMA arm's is nearly flat, 1.89 -> 1.93. NUMA-TP wins by SCALING
better in S, not by being faster per unit work. Reconciliation overhead is
roughly constant per token, so it dominates at short S and is amortised away
once the baseline's quadratic attention term takes over.

DEFECT 6 FIXED: alias-prefix derivation in _numa_propagate_buffer_alias.

  The prefix was taken from the post-reduction re-clone names (_numa_ar)
  instead of the plan prefix (_numa_p{plan_id}) that
  generate_numa_shard_allocations used for the placeholder allocations the
  alias is meant to supersede. Consequences: the alias matched no
  placeholder, so it was never consumed; the placeholder allocation
  survived; and the accumulator clones added by defect-4's fix stayed as
  full per-socket copies instead of collapsing into cheap reinterprets.

  Generated code, GPT-2 117M W=4 (identical at S=2048 and S=4096):
    before   232 _numa_ar_ names, 12 dead, 96 clone defs
    after     96 _numa_ar_ names,  0 dead, 96 clone defs
